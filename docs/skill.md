# 登録手順 Skill (log-workout)

手書きノートの写真やテキストメモから training-logger へ筋トレ記録を登録するための Claude 向け Skill（Agent Skills 形式）の仕様・導入・利用手順を記述する。

---

## 概要と MCP との棲み分け

training-logger では、MCP サーバと Skill の責務を明確に分離している。

- **MCP サーバ (`POST /mcp`)**: トレーニング記録の CRUD、履歴照会、Atlas筋肉割当、および GitHub issue 起票による機能リクエストなどの **機能（ツール）** を提供する。
- **Skill (`log-workout`)**: 手書きノートの写真読み取り、不明箇所のヒアリング、Markdown 表による下書き提示、ユーザーの明示承認の取得、機能リクエストの誘導といった **登録の「手順（ワークフロー）」** を LLM に指示する。

MCP サーバ単体でもサーバーレベルの `instructions` により基本的な解釈（JST、速記法、追記原則など）は行われるが、Skill を導入することで「勝手な推測登録の防止」「確実な下書き確認」「体系的な機能リクエスト」が実現され、登録の精度と安全性が大幅に向上する。

---

## 導入手順

### 1. claude.ai

claude.ai の Web インターフェースで Skill を登録する。

1. `https://training-logger.discord.jp/skills/log-workout.zip` をダウンロードする（または本リポジトリの `public/skills/log-workout.zip` を使用）。
2. claude.ai を開き、**Settings** > **Capabilities** > **Skills**（またはチーム/プロジェクトの Skills 設定）に移動する。
3. **Upload Skill** をクリックし、ダウンロードした `log-workout.zip` をアップロードする。
4. 有効化されていることを確認する。

> **Cloudflare Access に関する注意**:
> 本番環境の Worker が Cloudflare Access により保護されている場合、外部ブラウザや claude.ai から `https://training-logger.discord.jp/skills/*` へのアクセスが遮断されることがある。その場合は Cloudflare Zero Trust の Access ポリシーにて `/skills/*` パスに対する Bypass ルールを設定するか、リポジトリから zip を直接取得してアップロードすること。

### 2. Claude Code

Claude Code ではリポジトリ配下またはユーザーディレクトリの `.claude/skills/` に配置された Skill が自動認識される。

- **リポジトリ内（自動認識）**:
  本リポジトリのルートに `.claude/skills/log-workout` がシンボリックリンク（`../../skills/log-workout` への相対リンク）として配置されているため、本リポジトリを作業ディレクトリとして Claude Code を起動すれば、何もしなくても自動で `/log-workout` が利用可能になる。
- **グローバル導入（他リポジトリや作業ディレクトリ外で使う場合）**:
  `skills/log-workout` ディレクトリを `~/.claude/skills/` 配下へコピーまたはシンボリックリンクする:
  ```bash
  mkdir -p ~/.claude/skills
  cp -r skills/log-workout ~/.claude/skills/
  # または
  ln -s /path/to/training-logger/skills/log-workout ~/.claude/skills/log-workout
  ```

### 3. Claude Desktop / ChatGPT の場合

- **Claude Desktop / ChatGPT**:
  現在のところ Agent Skills / Custom Skills の動的インポート機能には対応していない。
  これらのクライアントでは、MCP サーバが `InitializeResult` で返すサーバーレベルの `instructions`（`docs/mcp-server.md` 参照）によって最低限の速記解釈や追記ルールが担保される。

## 利用例（会話の流れ）

Skill 適用時の標準的な対話フロー（画像添付 → 不明点の質問 → 下書き提示 → 承認 → 登録 → 機能リクエスト）の例を以下に示す。

### 1. 画像添付と記録依頼
**ユーザー**:
> （手書きノートの写真を添付して）
> 今日の筋トレ記録を登録して！

### 2. 不明点の質問（1ターンに集約）
**Claude (Skill 適用中)**:
> ノートの写真を拝見しました。正確に記録するため、以下の点について確認させてください:
>
> 1. **種目名**: 3行目の種目は「アダクター（内転筋）」でお間違いないでしょうか?
> 2. **単位**: アダクターの重量「50」「45」の単位はポンド（lbs）ですか、それとも kg ですか?
> 3. **計画と実績**: レッグレイズに「計画20x2s → 20/10/10」とあります。最初の2セットが計画で、その後の3セットが実績という解釈でよろしいですか?
>
> 回答をいただき次第、下書きを作成します。

### 3. ユーザーの回答
**ユーザー**:
> 1. アダクターで合ってます。
> 2. lbs です。マシンの表示がポンドでした。
> 3. そうです。2セット予定してたけどきつくて回数分けて3セットやりました。

### 4. 下書きの提示と承認依頼
**Claude (Skill 適用中)**:
> ありがとうございます。以下の内容でワークアウトを登録します。内容をご確認ください。
>
> **セッション情報**:
> - **日付**: 2026-08-16 (JST)
> - **目的**: ダイエット
>
> **登録種目・セット一覧**:
> | # | 種目名 | セット | 回数 | 重量/値 | 単位 | 区分 | メモ |
> |---|---|---|---|---|---|---|---|
> | 1 | ウォーキング | 1 | - | 10分 (3.5~5.0km/h, 傾斜0.5%) | - | 実績 | ウォームアップ |
> | 2 | アダクター | 1 | 20 | 50 | lbs | 実績 | |
> | 2 | アダクター | 2 | 20 | 45 | lbs | 実績 | |
> | 3 | レッグレイズ | 1 | 20 | - | - | 計画 | 肩を上げない |
> | 3 | レッグレイズ | 2 | 20 | - | - | 計画 | 肩を上げない |
> | 3 | レッグレイズ | 3 | 20 | - | - | 実績 | 足を下げると浮く |
> | 3 | レッグレイズ | 4 | 10 | - | - | 実績 | |
> | 3 | レッグレイズ | 5 | 10 | - | - | 実績 | 手首注意 |
>
> 間違いや変更したい点があればご指摘ください。問題なければ「**登録して**」とお伝えください。

### 5. 新規種目を含む場合の対象筋確認

新規種目が下書きに含まれる場合は、対象筋の筋頭・左右まで確認し、同じ承認に含める。

**Claude (Skill 適用中)**:
> 「ヒップスラスト」は未登録です。一般的な両脚フォームから、主な対象を大殿筋（左右）、補助・安定化を大腿二頭筋（長頭・短頭、各左右）、半膜様筋（左右）、半腱様筋（左右）と推測しました。`list_atlas_muscles` で各筋頭・筋肉の左右別 ID を確認済みです。この対象筋を下書きに含めて、新規種目とワークアウトを登録してよいですか? 修正・追加があれば教えてください。

**ユーザー**:
> その内容で登録してください。

**Claude (Skill 適用中)**:
> （確認時に実際に返された Atlas ID を指定して MCP ツール `register_exercise` を実行）
>
> `register_exercise` から重複エラーと既存種目が返されました。返された内容は次のとおりです。
> - **名前**: （返された既存種目名）
> - **別名**: （返された別名）
> - **現在の対象筋**: （返された対象筋）
>
> この種目のことですか?

**ユーザー**:
> はい、この種目です。対象筋は現在のまま変更せず、ワークアウトだけ登録してください。

**Claude (Skill 適用中)**:
> （返された既存種目名で MCP ツール `log_workout` を 1 回実行。`set_exercise_muscles` は実行しない）

対象筋は、ユーザーが変更を明示的に望んだ場合だけ、承認済みの割当全体を `set_exercise_muscles` に渡して置き換える。別の種目だと答えた場合は、名前または別名を変更して `register_exercise` をやり直す。

### 6. 承認と登録
**ユーザー**:
> 問題ありません。登録してください。

**Claude (Skill 適用中)**:
> （MCP ツール `log_workout` を 1 回実行）
>
> 2026-08-16 のワークアウトを登録しました！
> - **登録種目**: 3 種目（ウォーキング、アダクター、レッグレイズ）
> - **合計セット数**: 8 セット（計画 2 セット、実績 6 セット）
>
> 同日の記録は追記として保存されます。内容を修正したい場合はいつでもお知らせください。

### 7. スキーマ外項目の機能リクエスト
**Claude (Skill 適用中)**:
> なお、ノートの余白に「心拍数 135bpm」「セット間休憩 60秒」のメモがありました。
> 現在の training-logger では心拍数や休憩時間の専用フィールドに対応していません（今回はセットメモに記載しました）。
>
> 今後のアップデート要望として、GitHub issue に機能リクエストを起票しますか?

**ユーザー**:
> お願いします。心拍数と休憩時間は毎回測ってるので欲しいです。

**Claude (Skill 適用中)**:
> （MCP ツール `create_feedback` を実行）
>
> 機能リクエストを作成しました:
> - **Issue**: [セットごとの心拍数・休憩時間の記録対応](https://github.com/japan4415/training-logger/issues/...)
>
> ご要望ありがとうございました！

## 更新手順

Skill の手順やプロンプトを更新する際は、以下のフローで作業を行う。

1. **正本の編集**:
   `skills/log-workout/SKILL.md` を編集する。
2. **ビルドスクリプトの実行**:
   ```bash
   pnpm run build:skill
   ```
   このコマンドにより、以下が自動実行される:
   - `skills/log-workout/` 配下のファイルが `public/skills/log-workout/` へ同期コピーされる。
   - 決定論的な STORE zip `public/skills/log-workout.zip` が再生成される。
3. **検証**:
   ```bash
   unzip -l public/skills/log-workout.zip
   pnpm run lint
   ```
4. **コミット**:
   変更した `skills/log-workout/SKILL.md` および生成された `public/skills/` を合わせて git commit する。
